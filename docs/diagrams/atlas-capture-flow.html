Atlas / capture & processing / 02

Capture first.
Recover honestly.

Proposed state flow for quick capture. The original reference must survive parsing/indexing failures; a UI should not say "saved and ready" before the promised stages finish.

Invariant

Once the initial save is confirmed, keep the original reference even if enrichment fails.

Honest state

Separate saved, processing, partially processed, ready, failed, and retrying outcomes.

Recovery

Expose retry, manual metadata, keep-in-inbox, and explicit dismissal. Never silently drop the item.

Implementation unknowns: storage durability, processing queue, retry limits, indexing, offline behavior, and import providers must be decided and verified before this is treated as production behavior.
