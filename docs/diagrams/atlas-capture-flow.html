Atlas / capture & processing / 02

Capture first.
Recover honestly.

Proposed behavior: preserve the original reference once saving succeeds, and give the user an accurate processing state with retry or defer choices.

Invariant

After a successful save, a processing failure must not silently erase the original reference.

Honest status

Keep “saved”, “processing”, “partially processed”, “ready”, and “failed” distinct.

Recovery

Retry is bounded and observable. Keeping the item in the inbox is not a failed save.

Still unconfirmed: transaction boundary, durable store, queue, retry schedule, indexing approach, and offline synchronization. This is product behavior to implement and test, not current deployed behavior.
