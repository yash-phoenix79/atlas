Atlas / system boundaries / 03

Proposed boundaries,
not assumed infrastructure.

Illustrative responsibility map for a multi-user Atlas. It shows separation of concerns and trust boundaries, not a claim that these services or technologies are already deployed.

Security is server-side

Authorization must be enforced by the API and data-access layer, not trusted to client-supplied IDs.

Derived data is rebuildable

Search indexes and extracted metadata need explicit retention, invalidation, and failure semantics.

AI is a boundary crossing

Model calls require policy, minimization, provenance and opt-out decisions—not invisible magic.

Open decisions: deployment topology, database and blob provider, job queue, auth provider, vector index, secrets handling, observability, tenant isolation, retention, and AI provider are not selected here. Choose them in reviewed architecture decisions, not in this diagram.
