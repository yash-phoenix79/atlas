One resource identity.
Multiple contexts.

Core conceptual model for personal content and its placements. Junction entities make many-to-many relationships explicit. This is not a physical database schema.

Resource is the canonical itemCollectionMembership implements the collection/resource many-to-many relationshipCardinality is conceptual pending schema review
No duplicate resources per view

A collection or board points to a Resource; it does not own an independent copy of the content.

Joins are explicit

CollectionMembership represents many-to-many organization. BoardPlacement is a separate record because placement differs per board.

Import state is recoverable

ImportJob tracks attempts and errors separately from the canonical resource identity.

Still unresolved: whether re-imports create new Resource versions or new records, exact ownership and sharing rules, file/blob persistence, annotation versioning, and deletion/retention semantics. These require explicit decisions before physical schema design.
